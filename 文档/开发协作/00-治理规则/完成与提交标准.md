# 完成与提交标准

任务只有同时满足以下条件才算完成：

1. 身份：修改人和对话已登记，任务板、认领和 Git 提交能相互对应。
2. 范围：只修改已认领路径，无未说明的附带变化。
3. 功能：任务验收条件全部通过，失败路径有明确处理。
4. 测试：新增或更新相应测试并实际运行；结果写入核对报告。
5. 兼容：涉及界面时验证桌面与 390px 手机视口、键盘操作和空状态。
6. 安全：鉴权、输入校验、越权、敏感日志和文件边界已检查。
7. 数据：迁移可重复、状态迁移合法、时间和金额格式符合约束。
8. 契约：接口和领域类型与共享契约一致；破坏性变化有版本或迁移方案。
9. 文档：用户行为、运行方式和已知限制同步更新。
10. 核对：存在核对报告，`git diff --check`、任务测试和治理校验均有真实结果。
11. 提交：实现提交包含任务号和修改人编号，提交哈希已写入修改确认。
12. 确认：项目所有者已在确认记录中同意合并。
13. 回溯：确认记录说明查看差异和安全回退方法。
14. 清理：无调试账户、密钥、临时数据库、悬挂服务和无意义生成物。

任务状态必须按顺序流转：

```text
计划中 → 可开始 → 开发中 → 待核对 → 待确认 → 已确认 → 已完成
```

“已阻塞”和“已取消”是异常状态。核对失败返回“开发中”；要求修改后必须重新核对并生成新的实现提交。项目所有者确认前，任何人都不得把任务标记为“已确认”或“已完成”。
