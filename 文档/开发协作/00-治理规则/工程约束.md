# 工程约束

## 技术方向

- 客户端：TypeScript 响应式 Web/PWA；原型迁移期间允许保留现有原生 JavaScript。
- 服务端：TypeScript Node.js 模块化单体，REST API；实时消息可使用 WebSocket。
- 数据：开发环境 SQLite，生产目标 PostgreSQL；迁移脚本必须可重复执行。
- 文件：本地开发使用隔离目录，生产使用 S3/OSS 兼容对象存储。
- 缓存/队列：首版按需引入 Redis，不能让 Redis 成为唯一事实来源。

## 强制不变量

- 用户、订单、报名、消息和资金记录使用不可预测的服务端 ID。
- 时间以 UTC 存储，界面按用户时区展示。
- 金额用整数分，禁止浮点记账。
- 所有写 API 支持鉴权、输入校验和审计上下文。
- 选人、验收、退款等状态变化使用事务和乐观版本号。
- 文件上传必须校验大小、扩展名、MIME、哈希与病毒扫描状态。
- 日志不得包含密码、令牌、完整消息附件或个人证件内容。

## 当前原型限制

`localStorage`、Canvas 演示二维码和模拟余额只能存在于原型适配层。生产模块不得依赖这些实现；所有演示入口必须持续显示“不会产生真实交易”。

## 依赖原则

- 优先使用维护活跃、许可清晰的依赖；新增依赖需要说明用途和替代方案。
- 不在浏览器中放置服务端密钥。
- 共享类型放在 `src/shared/`，前后端不得复制出不同版本的订单状态枚举。
