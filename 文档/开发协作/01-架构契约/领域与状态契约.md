# 领域契约 v1

本文件是前后端共享事实。变更状态、关键字段或不变量必须建立独立契约任务。

## 核心实体

- `User`：统一身份；可同时发布和报名。
- `Task`：公开需求与预算、分类、截止时间、完成标准。
- `Application`：候选人的方案、小样、报价和预计用时。
- `Assignment`：发布方从报名中选定的一位协作者。
- `OrderMessage`：选人后参与者之间的订单内消息。
- `Delivery`：可多版本提交的交付说明与文件集合。
- `Acceptance`：通过或退回修改的验收结果。
- `SettlementRecord`：当前仅记录演示结算结果，不能代表真实资金。
- `OrderEvent`：只追加的领域审计事件。

## Task 状态

| 状态 | 进入条件 | 可执行操作 |
|---|---|---|
| `draft` | 发布方保存草稿 | 编辑、提交审核、删除 |
| `open` | 审核通过并公开 | 提交/修改/撤回报名、发布方下架或选人 |
| `in_progress` | 发布方选定有效报名 | 双方沟通、协作者提交交付、申请取消 |
| `submitted` | 协作者提交一个交付版本 | 发布方验收通过或退回修改 |
| `pending_payment` | 演示结算订单验收通过 | 发布方确认演示付款 |
| `completed` | 验收和结算确认完成 | 评价、归档 |
| `cancelled` | 合法取消条件满足 | 查看原因与退款/释放记录 |
| `disputed` | 任一参与方在允许阶段发起争议 | 补充证据、平台裁决 |

退回修改从 `submitted` 回到 `in_progress`，保留历史交付版本。

## Application 状态

- `pending`：可由申请人修改或撤回；
- `selected`：唯一入选报名，与 Assignment 一一对应；
- `not_selected`：任务已选其他人；
- `withdrawn`：申请人在选人前主动撤回。

## 领域不变量

1. 发布方不能报名自己的需求。
2. 同一用户对同一开放需求最多一份未撤回报名。
3. 只有需求发布方可以选人。
4. 每个需求最多一个有效 Assignment。
5. 选人时需求必须为 `open`，报名必须为 `pending`。
6. 只有发布方与已选协作者可以读取/发送订单消息。
7. 只有已选协作者可以提交交付，只有发布方可以验收。
8. 完成状态不可回退；争议/取消需产生独立事件。
9. 领域写入必须携带 `expectedVersion`，避免并发选人或重复验收。
10. 所有状态变化写入 `OrderEvent`，事件不可覆盖删除。

## 金额与时间

- API 金额字段以整数分结尾，例如 `budgetCents`、`quoteCents`。
- 存储时间使用 UTC ISO 8601；客户端自行本地化。
- 选人后订单约定价取入选报名报价，并保留发布预算快照。
