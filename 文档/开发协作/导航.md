# 开发协作导航

这套文件用于让不同开发者、不同 Codex 对话或自动化执行者同时推进项目，并让项目所有者随时知道修改人、开发进度、核对结果和回退位置。

## 目录地图

| 分类 | 内容 | 主要维护者 |
|---|---|---|
| `00-治理规则/` | 产品边界、工程约束、协作协议、完成标准 | 协调者 |
| `01-架构契约/` | 当前/目标架构、领域状态、接口契约 | 契约负责人 |
| `02-开发计划/` | 总路线图和依赖关系 | 协调者 |
| `03-并行工作流/` | 每条工作流的范围、依赖和路径所有权 | 对应工作流负责人 |
| `04-交接与确认/` | 提交前核对、修改确认流程、决策记录和模板 | 所有参与者 |
| `协作记录/` | 人员、对话、任务、认领、核对、确认和交接实例 | 按 `AGENTS.md` 更新 |
| `.agents/` | 工具固定目录和机器可读入口 | 仅协调者 |

## 开始一个任务

1. 阅读根目录 `AGENTS.md` 和 `.agents/项目入口.json`。
2. 在 `协作记录/人员与对话/人员登记表.md` 登记修改人和本次对话。
3. 从 `协作记录/任务进度/任务板.json` 选择“可开始”且依赖已完成的任务。
4. 阅读任务所属工作流文档，检查负责路径没有与有效认领重叠。
5. 新建 `协作记录/任务认领/认领-<任务号>-<修改人编号>.json`。
6. 在独立 `work/<任务号>-<标识>` 分支开发，只修改认领范围。

## 完成一个任务

```text
开发中 → 待核对 → 实现提交 → 待确认 → 项目所有者确认 → 合并 main → 已完成
```

1. 完成计划后停止扩展范围，把任务改为“待核对”。
2. 按 `04-交接与确认/提交前核对清单.md` 实际运行检查并保存核对报告。
3. 核对通过才允许创建实现提交，提交中包含任务号和修改人编号。
4. 使用实现提交哈希创建修改确认记录，把任务改为“待确认”。
5. 项目所有者确认后才允许合并主分支；合并提交构成稳定回退点。

## 当前开发现实

- 已有产品：响应式、本地持久化的可交互原型。
- 已有流程：发布、初版报名、比较选人、订单对话、交付、修改、验收、演示结算。
- 尚未实现：服务端多用户同步、真实身份、数据库、真实文件存储、通知、风控和真实支付。
- 当前最大技术债：`app.js` 是前端单体，必须先模块化才能让多个前端任务安全并行。

机器可读进度以 `协作记录/任务进度/任务板.json` 为准，人工总览以同目录的 `开发进度总表.md` 为准。
