# 并行开发入口

这套文件用于让不同开发者、不同 Codex 对话或自动化代理同时推进项目，同时避免产品规则、接口和文件互相冲突。

## 目录地图

| 分类 | 内容 | 谁可以修改 |
|---|---|---|
| `00-governance/` | 产品边界、工程约束、协作协议、完成标准 | 协调者；普通任务仅可提变更建议 |
| `01-architecture/` | 当前/目标架构、领域状态、API 契约 | 契约负责人 |
| `02-plans/` | 总路线图和依赖关系 | 协调者 |
| `03-workstreams/` | 每条可并行工作流的范围和路径所有权 | 对应工作流负责人 |
| `04-handoffs/` | 任务模板、交接记录和决策日志 | 所有参与者按模板新增文件 |
| `.agents/` | 机器可读的项目、工作流、任务板和认领协议 | 按文件规则执行 |

## 开始一个任务

1. 从 `.agents/task-board.json` 选择 `ready` 且无未完成依赖的任务。
2. 阅读任务的 `workstreamId` 对应文档。
3. 确认任务的 `ownedPaths` 与其他认领没有重叠。
4. 在 `.agents/claims/` 新建认领 JSON。
5. 只在认领范围内开发并运行指定测试。
6. 完成后新增交接文档，由协调者合并并更新任务板。

## 当前开发现实

- 已有产品：响应式、本地持久化的可交互原型。
- 已有流程：发布、初版报名、比较选人、订单对话、交付、修改、验收、演示结算。
- 尚未实现：服务端多用户同步、真实身份、数据库、真实文件存储、通知、风控和真实支付。
- 当前最大技术债：`app.js` 是前端单体，必须先模块化才能让多个前端任务安全并行。

## 建议的并行启动波次

- 波次 0：协调者冻结领域/API 契约；前端负责人拆分单体；QA 负责人建立独立测试基线；合规负责人调研作业与支付边界。四者路径不重叠，可并行。
- 波次 1：账号服务、需求/报名/选人服务、前端页面迁移可基于冻结契约并行。
- 波次 2：订单消息、文件交付、通知、审核后台并行。
- 波次 3：真实支付仅在调研和合规决策通过后开始。

机器可读状态以 `.agents/` 为准，文字路线图用于解释原因和验收方式。
