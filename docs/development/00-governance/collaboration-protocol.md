# 多人/多对话协作协议

## 角色

- 协调者：维护任务板、共享契约、依赖和合并顺序。
- 工作流负责人：只负责一个工作流的文件和交付。
- 契约负责人：审核领域/API 的兼容性变化。
- QA 负责人：维护独立验收证据，不替功能负责人掩盖失败。

## 认领

认领文件名：`.agents/claims/CLAIM-<taskId>-<actor>.json`。

认领前必须检查：任务为 `ready`；所有依赖为 `done`；路径没有被其他有效认领覆盖。认领有效期默认 24 小时，超时只能由协调者回收。

## 路径冲突

- 两个活跃任务不能拥有相同文件或父子通配路径。
- 发现意外重叠时，后认领者立即停止写入并留下冲突说明。
- 共享契约变更单独建立任务，不夹带在功能任务中。

## 分支与合并

- 分支建议：`work/<taskId>-<slug>`；提交信息以任务号开头。
- 合并顺序：共享契约 → 服务端实现 → 客户端实现 → 端到端测试/文档。
- 每次合并只解决当前任务，不顺手格式化全仓库或移动无关文件。

## 交接

交接文件名：`docs/development/04-handoffs/HANDOFF-<taskId>-<date>.md`。没有交接文件的任务不能标记为完成。
